Linux 常用系统状态查看命令

知知行笔记·2026-10-27·约 8 分钟阅读
linuxoperationsnetworktroubleshooting

日常检查系统、CPU、内存、磁盘、进程、网络、服务和日志的速查笔记。不绑定具体项目，以查看命令为主；部分命令需要 sudo 权限或对应工具已安装。

每组命令下方附解释或示例。示例 IP 192.0.2.10 为文档专用地址，PID、服务名和目录均需按实际情况替换；示例结果不代表当前服务器状态。

1. 系统信息与运行时间

cat /etc/os-release   # 系统发行版
uname -a              # 内核版本、主机架构等
date                  # 当前日期、时间与时区
timedatectl           # 时间、时区和同步状态
uptime                # 运行时长、登录人数、平均负载
uptime -s             # 最近一次开机时间

示例：uptime 显示 up 23 days，表示已连续运行约23天。末尾 load average: 0.20, 0.35, 0.40 分别为最近1、5、15分钟平均负载，不能当作20%、35%、40%的 CPU 使用率。负载需结合 CPU 核数、CPU 占用和 I/O 等待判断。

2. CPU与实时监控

nproc                 # 当前进程可用的处理器数量
lscpu                 # CPU型号、架构、逻辑CPU等
top                   # 实时查看CPU、内存和进程

示例：nproc 输出 8，表示当前进程可用的处理器数量为8。容器或资源限制可能使其与整台机器的逻辑 CPU 数不同。top 中可观察哪个进程的 %CPU 或 %MEM 较高。

top怎么退出

按键 效果
q 退出 top
Ctrl+C 通常也可退出 top

两种方式都只是结束监控界面，不会停止被查看的进程或服务。 这是在前台运行 top 时的行为，不要将其他命令中的 Ctrl+C 理解为也不会影响其运行。

3. 内存、Swap与系统采样

free -h               # 内存与Swap，按易读单位显示
vmstat 1 5            # 每秒采样一次，共输出5次

示例：free -h 中 available 为 5.2Gi，表示估计还有约5.2GiB可供新应用使用。判断内存余量优先看 available，不要只看 free，因为部分缓存可回收。

vmstat 1 5 第一行通常是开机以来的平均值，后续行反映采样期间的变化。si/so 持续较高可提示 Swap 换入换出活跃；wa 较高可提示 I/O 等待，但仍需结合其他指标分析。

4. 查找进程与资源占用

# CPU占用最高的前10个进程，包含一行表头
ps -eo pid,ppid,comm,%cpu,%mem --sort=-%cpu | head -n 11

# 内存占用最高的前10个进程
ps -eo pid,ppid,comm,%cpu,%mem --sort=-%mem | head -n 11

# 查找命令行含java的进程
pgrep -af java

# 查看指定进程的父进程、启动时间、运行时长、状态及完整参数
ps -ww -p 15164 -o pid,ppid,lstart,etime,stat,args

示例：若实际 PID 为24680，把最后一条中的 15164 换为 24680。etime 是运行时长，lstart 是启动时间，ppid 是父进程ID。ps 的 %CPU 通常反映进程生命周期内的 CPU 使用比例，不是与 top 完全相同的即时采样。

按路径搜索不到进程时，可换进程名查询，例如 pgrep -af node-red；程序可能改写进程标题。需要同时核对监听端口的进程归属。

5. 磁盘、分区与目录占用

df -h                            # 各文件系统的容量和剩余空间
df -i                            # inode使用情况
lsblk -f                         # 磁盘、分区、文件系统及挂载点
du -sh /var/log                   # 指定目录的总占用
du -h --max-depth=1 . | sort -h    # 当前目录下一层占用，按大小升序

示例：df -h 显示 / 使用率95%，再按具体目录执行 du 定位大目录。du -sh /var/log 返回 2.3G /var/log，表示日志目录占约2.3GB。若空间未满却无法创建文件，继续检查 df -i 是否 inode 耗尽。

df看文件系统是否满，du找目录占用。 大目录扫描可能较慢，先查具体目录；没有权限读取的内容会影响 du 的统计完整性。

6. IP、路由、端口和连接

ip -br addr                       # 简洁显示网卡、状态和IP
ip route                          # 路由与默认网关
sudo ss -lntp                     # TCP监听端口及进程
sudo ss -lnup                     # UDP端口及进程
ss -s                             # 套接字状态汇总
sudo ss -lntp 'sport = :1880'      # 指定TCP监听端口

示例：ss 显示 *:1880、pid=15164，可据此核对该端口所属进程。若显示 127.0.0.1:1880，则仅监听本机回环地址，外部无法直接通过网卡地址访问。查8080时，把最后一条的1880换成8080。

7. 网络连通性与HTTP响应

ping -c 4 192.0.2.10
nc -vz -w 3 192.0.2.10 8080
curl -I --connect-timeout 3 --max-time 5 http://127.0.0.1:1880/

示例：替换服务器IP后，第一条发送4次 Ping，第二条尝试连接8080端口，第三条检查本机1880的 HTTP HEAD 响应。nc 需已安装，选项以本机实现为准。

  • Ping不通可能是禁用ICMP；Ping通不代表应用端口可用。
  • TCP连通不代表认证或业务功能正常。
  • 返回200表示该请求成功；401、403、404等也说明收到了HTTP响应，需继续核对路径、权限和响应来源。
  • 接口不支持HEAD时，用 curl -i URL 对已确认的只读GET接口验证。

8. 系统服务与日志

systemctl --failed
systemctl list-units --type=service --state=running
systemctl status sshd --no-pager -l
journalctl -u sshd -n 100 --no-pager
journalctl --since "1 hour ago" --no-pager
sudo journalctl -k -b --no-pager

示例：systemctl --failed 列出失败单元；status sshd 查看SSH服务状态；journalctl -u sshd 查看它最近100条日志。服务名因系统不同可能是 ssh，应使用实际名称。日志是否完整取决于权限和保留策略。

最后一条中的 -k 表示内核日志，-b 表示本次开机。手动通过 nohup 启动的程序不一定有对应 systemd 服务单元，需查询它实际重定向的日志文件。

查看文件日志：

tail -n 100 /var/log/messages
tail -F /var/log/messages

示例：第一条读取最后100行，第二条持续跟踪，并在轮转后尝试继续跟踪同名文件。Ctrl+C 只退出 tail，不会停止产生日志的服务。部分系统没有 /var/log/messages，可使用 journalctl；应用日志则替换为实际路径。

9. 登录、重启与OOM记录

w
last -n 10
last -x -F | head -n 20
sudo journalctl -k -b --no-pager |
  grep -Ei 'out of memory|oom-kill|killed process'

示例：w 查看当前登录会话；last 查看历史登录；last -x 包含重启和关机记录。若内核日志出现 Killed process 12345 (node) 等OOM记录，应结合时间、PID和应用日志判断是否是目标服务。

查不到记录不等于没发生过：日志可能没有保留，且这里的OOM命令只查本次开机。登录记录也不能单独证明某个用户停止了服务。

10. 日常先记住这8条

uptime                 # 运行时间与平均负载
top                    # 实时CPU与进程；q或Ctrl+C退出
free -h                # 内存，重点看available
df -h                  # 文件系统空间
df -i                  # inode
sudo ss -lntp          # TCP监听端口及进程
systemctl --failed     # 失败单元
journalctl -n 100       # 最近100条系统日志

示例：发现访问变慢，先用 uptime、top、free -h 查看负载和资源，再用 ss 确认端口、用日志定位错误，不要直接重启全部服务。
